# Telegram Sender

Приложение на Python для рассылки сообщений в несколько Telegram-групп. Рассылку выполняет авторизованный Telethon-аккаунт, а отдельный BotFather-бот даёт удобное меню управления в управляющей группе.

Подробная инструкция для пользователя: [USER_GUIDE.md](USER_GUIDE.md).

## Возможности

- выбор нескольких групп через кнопочное меню;
- однократная и повторяющаяся рассылка;
- настройка интервала между отправками;
- несколько рассылок по расписанию без пересечения по времени;
- автоматическая статистика по завершении;
- роли владельца и администратора;
- интерфейсное меню BotFather-бота.

## Требования

- Python 3.10+;
- Telegram-аккаунт с `@username` для Telethon;
- Telegram-приложение с `API_ID` и `API_HASH`;
- BotFather-бот для меню;
- управляющая Telegram-группа.

## Установка

```powershell
py -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

## Настройка

Создайте файл `.env` в корне проекта:

```env
API_ID=12345678
API_HASH=ваш_api_hash
CONTROL_GROUP_ID=-1001234567890
BOT_TOKEN=123456789:токен_бота_из_BotFather
```

| Переменная | Назначение |
| --- | --- |
| `API_ID` | Идентификатор Telegram-приложения. |
| `API_HASH` | Секретный хеш Telegram-приложения. |
| `CONTROL_GROUP_ID` | Числовой ID управляющей группы. |
| `BOT_TOKEN` | Токен BotFather-бота, который показывает меню. |

Добавьте BotFather-бота в управляющую группу. При первом запуске Telethon запросит вход в Telegram-аккаунт; сессия сохранится в `sessions/sender.session`.

## Запуск

```powershell
.\venv\Scripts\python.exe main.py
```

После запуска интерфейсный бот отправляет меню в управляющую группу. Если меню не отображается, отправьте команду `/menu`.

## Развёртывание на Linux-сервере

Для постоянной работы рекомендуется Ubuntu/Debian VM. До запуска добавьте SWAP: он защищает процесс от аварийного завершения при кратковременной нехватке RAM. Для сервера с 1 GB RAM используйте 1–2 GB SWAP.

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
free -h
```

### Вариант 1: Docker Compose

Установите Docker Engine и Docker Compose, скопируйте проект на сервер и создайте `.env`. Для первого входа Telethon запустите контейнер в интерактивном режиме:

```bash
docker compose run --rm telegram-sender
```

Введите номер телефона и код Telegram. Сессия будет сохранена в папке `sessions/` на сервере. Затем запустите сервис в фоне:

```bash
docker compose up -d --build
docker compose logs -f
```

`restart: unless-stopped` в [docker-compose.yml](docker-compose.yml) автоматически поднимет контейнер после перезагрузки сервера. Папки `sessions/`, `data/` и `logs/` подключены как постоянные тома: Telethon-сессия, база и журналы не исчезнут при пересоздании контейнера.

### Вариант 2: systemd

Установите зависимости на сервере и создайте виртуальное окружение:

```bash
sudo apt update
sudo apt install -y python3 python3-venv
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
```

Скопируйте [deploy/telegram-sender.service](deploy/telegram-sender.service) в `/etc/systemd/system/telegram-sender.service`, предварительно заменив `User`, `WorkingDirectory` и `ExecStart` на реальные значения.

```bash
sudo cp deploy/telegram-sender.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now telegram-sender
sudo systemctl status telegram-sender
```

Просмотр логов службы:

```bash
journalctl -u telegram-sender -f
```

## Сохранность данных

Файл Telethon-сессии находится в `sessions/sender.session`; он сохраняется между перезапусками. Не удаляйте папку `sessions/` и не добавляйте её, `.env` или `data/bot.db` в публичный репозиторий.

## Управление из группы

В меню доступны кнопки:

- **Группы** — выбор получателей с переключателями;
- **Выбранные** — текущий набор групп;
- **Начать рассылку** — запрос текста и запуск повторной отправки;
- **Отправить один раз** — разовая отправка текста;
- **Интервал** — пауза между пакетами сообщений;
- **Запланировать** — создание рассылки на заданное время;
- **Планы** — просмотр и отмена будущих рассылок;
- **Статус** — текущее состояние;
- **Остановить рассылку** — показывается только при активной рассылке.

Рассылки запускаются только в выбранные группы. Для запланированной рассылки укажите:

```text
ЧЧ:ММ ДЛИТЕЛЬНОСТЬ_В_СЕКУНДАХ ИНТЕРВАЛ_В_СЕКУНДАХ ТЕКСТ
```

Например: `18:30 300 10 Напоминаем о встрече!`.

Планировщик не допускает пересекающихся по времени рассылок. Планы хранятся в памяти, поэтому программа должна работать до их выполнения; после перезапуска планы создаются заново.

## Доступ

Подключённый Telethon-аккаунт автоматически становится владельцем. Владельцу и администраторам доступно управление рассылками.

| Команда | Назначение |
| --- | --- |
| `/admins` | Показать роли. |
| `/admin_add @username` | Назначить администратора (только владелец). |
| `/admin_remove @username` | Снять права администратора (только владелец). |

## Важно

- Не публикуйте `.env` и файлы из `sessions/`.
- Используйте рассылку только в группах, которыми управляете.
- При ограничениях Telegram (`FloodWait`) увеличьте интервал между сообщениями.
